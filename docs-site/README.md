# Meridian documentation site

The user guide, tutorials and the API reference for `Meridian.Scripting`, built with [DocFX](https://dotnet.github.io/docfx/)
(pinned as a local .NET tool in `dotnet-tools.json`).

```bash
cd docs-site
dotnet tool restore
dotnet docfx metadata docfx.json            # API pages from src/Meridian.Scripting
dotnet docfx build docfx.json --warningsAsErrors
dotnet docfx serve _site                    # http://localhost:8080
```

The build needs no network access once the tool and NuGet packages are restored. It must stay free of warnings: the
GitHub workflow `.github/workflows/docs.yml` builds with `--warningsAsErrors` and deploys to GitHub Pages only when it
is started by hand.

| Folder | Content |
| --- | --- |
| `docs/` | the user guide, one page per feature area (`docs/toc.yml` orders them) |
| `tutorials/` | step-by-step walkthroughs |
| `api/` | `index.md` is hand-written; everything else is generated by `docfx metadata` and ignored by git |

Conventions:

- Describe behaviour that exists in the code; check labels against the UI source in `src/Meridian.Web/Components`.
- Mark missing screenshots as `> [!NOTE]` blocks starting with `**TODO (screenshot):**`, then put images in `images/`.
- The screenshots in `images/` come in a `-dark` and a `-light` version and are shown with `<picture>` (dark when the
  reader's system is dark). They are taken from the E2E fixtures; regenerate them all with
  `MERIDIAN_DOCS_SCREENSHOTS=1 dotnet test tests/Meridian.E2E --filter DocsScreenshotTests` (needs Playwright's
  Chromium, see `tests/Meridian.E2E/README.md`).
- The SysML v2 text and the scores quoted in the tutorials are checked by `tests/Meridian.Tests/DocsTutorialTests.cs`,
  and the scripting examples by `DocsExampleTests.cs`; update the tests when you change those pages.
